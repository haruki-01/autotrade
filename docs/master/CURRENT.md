## 1. 理想状態

### Phase 1 で「できた」と言える状態

Bybit の **BTC-USDT 1本**を、同じルールで **バックテスト → demo → 少額 live** まで通した bot が1つある。

| 層 | 到達イメージ |
|---|---|
| 口座 | 元本 300 USDT。1回の証拠金 30。レバ 3。同時建玉 **1枠**。複数口座・複数銘柄は作らない |
| 検証の合格 | 費用後 EV が 3期間ともプラス。最大 DD ≤ 20%。期間ごと n&lt;100 は不合格ではなく **判定保留**（プールの t で読む） |
| 存在理由 | 春希さんが一文で言える。「下落で買い持ちより壊れない」は数字で出ている。上昇期に買い持ちの Return/DD に負けてよい（合否ではない）が、そのとき **なぜ持たずに bot を回すか** は決めてある |
| 運用 | demo で注文とポジションがずれない。live はフラグと別キーなしでは起動しない |
| 非目標 | Web UI、2本目ロジック、秒スキャ、板の先頭 |

### 到達しないもの（別軸。合否にしない）

| 軸 | 扱い |
|---|---|
| **月120%**（元本300で月360 USDT） | 実測の最良 N×Q² の約17倍。願望・逆算用。詳細は [TARGET_MODEL.md](./TARGET_MODEL.md) |
| **月50エントリー** | 1枠・日足規模と両立しない。履歴として残すだけ |

「月120%を目指す」と「費用後に黒で DD を守る」は別のプロジェクトに近い。今の Phase 1 は後者。

## 4. いま検証・判断すべき論点

新しい入口条件を増やす段階ではない。論点は3つだけ。上から順。

### 論点A（判断・数字は揃っている）

**SH-01 を「DD を売るトレンド追随」として demo に出すか。**

- 出す: 上昇期に Return/DD で負けることを受け入れ、執行ギャップ（論点C）へ
- 出さない: シグナル探索に戻らない。次は論点Bか、この口座設計での探索を止める

### 論点B（実施済み 2026-08-25）

休む条件を中心設定に1点足した。正本: `eval/reports/20260825-slow-rest.md`。

- SMA と同じ向きだけ（50〜300日）は Set C の Return/DD を買い持ち（1.51）より上にする
- **3期間とも Return/DD で買い持ちを上回るのは `regime_50d` と `regime_100d`**
- `regime_100d` がプール t 最大（+3.01）
- 符号反転は Set C で EV マイナス
- ロングのみは C はわずかに勝ち、A はわずかに負ける

入口は増やしていない。月120%には届かない。次は論点A（これを採用して demo に出すか）。

### 論点C（live の前は必須。Aで「出す」なら次）

**研究データと本番の差。** lock は Binance Vision。Bybit 無期限・funding・約定（とくに日足規模のストップ）。demo で注文と建玉が一致するか。

合否の「エッジがあるか」ではなく、「同じルールを取引所に載せられるか」。

### 今やらないこと

- 12h / 利確1.5% の入口探索
- 月50回のための高速ロジック
- 6銘柄バスケットに戻す
- `min_trades` を下げる
- 月120%をゲートにする
- ノブの同時変更、期間を見て再最適化
