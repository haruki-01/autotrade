# 市場に対する優位性 — 評価軸

最終更新: 2026-08-25  
対象: 入口のトレードスポット仮説（①）を採点するとき  
前提: 市場には人と、すでに動いている bot がいる。bot は「人間より遅い裁量」だけではなく、公開OHLCV・公開建玉・公開funding を同じ時刻に同じルールで撃つ。

## 1. 先に決めること

優位性は「形がきれい」「1分足で速い」ではない。

問いはこれだけ:

> **同じ時刻に、人・定番インジbot・派生データbotのどれが、何を「トレンドだ」と思っているか。その認識と、実際に払わざるを得ないフローのあいだに、こちらだけが使えるズレがあるか。**

参考にした2型（春希さん）を、速さ競争に落とさない:

| 型 | 意味（採用） | 意味（採用しない） |
|---|---|---|
| **市場が認知できるトレンドの、より早期の検出** | 人間や遅めのトレンドbotが「1時間の高値切り上げ」とラベルする**前**に、別の層ではすでに強制フローが始まっている | 同じブレイクを 1秒早く取る。板・約定の速さ。他のbotが同じOHLCVルールで同時に撃つ形 |
| **市場が認知できないトレンドの検出** | 価格の形だけ見るとレンジ／だまし／押しに見えるが、建玉・誰が乗っているか・失敗した定番ブレイクなど、**別表現では方向がある** | 「秘密のインジ」。公開データなのに誰も見ていない、という根拠のない想定 |

**純粋な速さでは勝てない。** 他のbotが検知可能なトレンドを、同じトリガーで先に取る競争は、こちらが市場そのものになる（初動で滑り、直後に逆選択）。

## 2. 市場を3層で見る

採点のとき、反対側を「市場」と一括しない。

| 層 | 典型 | 何をトレンドだと思うか | こちらが速さで勝とうとすると |
|---|---|---|---|
| **人（裁量）** | 水平線、HH/HL、ニュース | 15分〜日足で「形が完成してから」 | 人が遅いので「完成前」は有利に見えるが、同じ完成条件をbotが先に撃つ |
| **定番bot** | EMA、Donchian、ORB、RSI、15分高値抜け、スクイーズ | 公開OHLCVの単純ルール。足の確定と同時に撃つ | **同時・同方向の混雑**。初回ブレイクは餌になりやすい |
| **派生bot** | OI、funding、taker、長短比 | 価格に出る前の情報の一部は、すでに「賢いbot」の定番 | データを足しただけでは非認知にならない。**二群に分ける使い方**が本体 |

個人botが持てる場所は、MARKET_EDGE_MAP どおり **秒の競争の外**。残るのは:

1. 定番botより**遅いが、相手が焼けたあと**（二階）
2. 遅めのトレンドbotより**物語が早い**（1時間がまだ未認定）
3. 価格botが**同じ陽線を区別できない分割**（OI増の突破 vs 買い戻しの突破）
4. **撃たない**（混雑側・費用が値幅を超える日）

## 3. 評価軸（6本）

各軸 **1〜10**。合計や平均で採用しない。**どれか1軸が 7 以上で、速さ競争（後述の失格）に該当しない**ことが最低ライン。  
6軸すべて 5 前後は、きれいな形でも優位なし。

### 軸1. 物語の早期性（速さではない）

人間や 1時間トレンドbot が「トレンド開始」とラベルするより前に、こちらが入る理由があるか。

| 点 | 目安 |
|---|---|
| 1–2 | 1時間HH完成のあと、定番どおり追随。市場と同じ認知のあと |
| 3–4 | 15分陽線・EMA・直前高値など、定番botと同じ完成条件を1分で撃つ（案2・BR-001系） |
| 5–6 | 上位足の完成を待つが、トリガーだけ1分。早期性はほぼ無い |
| 7–8 | 1時間はまだレンジ／未認定。下位の失敗や建玉の変化が「種」 |
| 9–10 | 価格が動く前から強制フローが見える（清算の初動そのもの）。個人は通常取れない |

**失格:** 「1分足だから早い」だけを理由にする。

### 軸2. 非認知性（同じチャートではトレンドに見えない）

同じOHLCVを見ている定番botが、この局面を「トレンドシグナル」として発火しにくいか。

| 点 | 目安 |
|---|---|
| 1–2 | Donchian、ORB、インサイド抜け、旗面抜けそのもの |
| 3–4 | 教科書の複合でも、条件はすべて公開足の形 |
| 5–6 | 失敗・二度目など経路依存。形だけでも書けなくはない |
| 7–8 | 価格はレンジ／だまし／弱い更新に見える。分割は建玉・誰が乗っているか・「定番が焼けた」など |
| 9–10 | 取引所の非公開板。個人データでは近似できない |

### 軸3. bot混雑耐性

同じルールを他botが量産したとき、こちらが先に滑って焼かれないか。

| 点 | 目安 |
|---|---|
| 1–2 | 足の確定と同時に、丸見え水準を成行で取る |
| 3–4 | 公開OHLCVの単純ルール。混雑そのものがエッジを消す |
| 5–6 | フィルタで回数は減るが、トリガー時刻は定番と同じ |
| 7–8 | 定番が撃った**あと**（失敗確定、水準の受け入れ、焼き）が本体。意図的に遅い |
| 9–10 | 他者が同じ状態を観測しにくい（データまたは経路が稀） |

### 軸4. 強制支払い

反対側が「意見が違った」ではなく、損切・清算・funding・在庫で払わざるを得ないか。

| 点 | 目安 |
|---|---|
| 1–2 | 誰が払うか書けない。インジが揃っただけ |
| 3–4 | 「遅れたDiscretionary」程度 |
| 5–6 | 水平のストップは想像できるが、強制かは弱い |
| 7–8 | 定番ブレイクの損切、overnight在庫、清算の代理（OI急減）など、フローが強制に近い |
| 9–10 | 清算カスケードの直撃。初動は取れないが機構は強い |

### 軸5. 情報の非対称（価格の形だけでは区別できない）

同じローソクを、別データまたは「失敗した経路」で二群に分けられるか。

| 点 | 目安 |
|---|---|
| 1–2 | 陽線か陰線か、EMAの上下だけ |
| 3–4 | 高値更新した／していない（定番botも同じ） |
| 5–6 | 経路（一度失敗した）がある。OHLCVだけだが時系列の記憶が要る |
| 7–8 | OI増減・長短比・現物と先物など、価格に出ない分割。公開データでも価格botは見ない |
| 9–10 | 非公開または取引所非互換で本番に使えない（高得点でも採用しない） |

### 軸6. この口座の枠に載るか

優位があっても、12h / 損切り1.00% / 利確1.50% / 月50回 / 1枠と矛盾すると使えない。

| 点 | 目安 |
|---|---|
| 1–2 | 日足規模・年数十回（SH系）。または毎分の速さ勝負 |
| 3–4 | 希少イベント中心で月50に届かない見込みが強い |
| 5–6 | 届くかもだが、利確1.5%が大勝ちを切る／幅1%がイベントと不一致 |
| 7–8 | 半日の継続を取りにいける。回数はゲートや箱の数で調整できる |
| 9–10 | 枠と歪みの時間尺度が一致している、と事前に言い切れる（検証前はほぼ付けない） |

## 4. 失格（点を付けない。捨てる）

1. **レイテンシ・板の先頭・清算の最初の1本**
2. **定番OHLCVルールの1分移植**（案2、BR-001〜004・007 の本体）
3. **すでに formal で棄却したEHを、説明を変えて再提出**（EH-02/03/04/05/08のOI蓄積単体/09）。機構が残ったもの（EH-01の二群、EH-06の向き、EH-07の希少）は「入口の分け方／拒否／遅延追随」に限定して再利用可
4. **インジを増やすことによる早期検知**

---

## 5. 採点の使い方

1. スポットを書くとき、3層（人 / 定番bot / 派生bot）それぞれがこの局面で何をするかを先に書く
2. 6軸を 10 段階＋一言
3. **総合は平均しない。** 「軸1か軸2が7以上」かつ「軸3が6以上」かつ失格なし、を目安にする
4. ③検証は、採点を合格にしない。採点は実装前の足切り

検証で勝っても、軸3が2なら「期間の運で定番が効いた」可能性を疑う。
