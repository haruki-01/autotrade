## 1. 目的

最短でも分足を判断材料とする自動売買ボットについて、**再現可能な仮説検証**により「月次 +3%（複利運用）」を執行コスト込みで達成しうるロジックを探索・採用する。

本スペースは「勝てるロジックのリサーチと検証」が主目的である。実装・本番稼働はその後段とする。

> **戦略コンテキスト（2026-09-06）**: 本 SPEC は **Layer 2 衛星（MP-CRYPTO-5M）** の正本。独立・不労所得の本体は [independence-strategy.md](research/independence-strategy.md) の Layer 1（NISA インデックス等）を参照。

## 2. 前提・制約（L0・変更時は再ベースライン）

### 2.1 市場・データ

| 項目 | 仕様 |
|---|---|
| 銘柄 | **BTC/JPY** |
| データ | BTC/JPY の OHLCV（研究・検証とも同一銘柄） |
| 時間足の下限 | **分足以上**（スキャルピングは対象外） |
| スキャル除外理由 | API遅延等により他botに構造的に不利 |

### 2.2 資金・リスク

| 項目 | 仕様 |
|---|---|
| バンクロール \(B\) | **¥50,000**（初期。複利で更新） |
| 1トレードあたり証拠金 | **\(B/10\)**（初期 ¥5,000） |
| レバレッジ | **2倍** |
| 建玉想定額 \(Q\) | **\(B/5\)**（2x レバ、初期 ¥10,000） |
| 同時建玉（初期） | 最大 2（証拠金合計 ≤ \(B \times 0.2\)） |
| 複利 | 月末に \(B \leftarrow B + P\)。翌月の証拠金・\(Q\) は新 \(B\) 基準 |

### 2.3 目標

| 項目 | 仕様 |
|---|---|
| 月次資金成長（Gate2） | **+3%**（\(P^* = 0.03 \times B\)、初期 **¥1,500**） |
| 必要1回あたり期待値 \(EV^*\) | **¥30 / 回**（N=50、\(Q\) 比 **+0.3%**） |
| Gate2 旧基準（参考） | +5%（¥2,500）— 2026-09-06 まで |
| 狙うトレード回数帯 \(N\) | **50回 / 月** |
| Stretch（参考・Gate 対象外） | 月次 +20%（¥10,000）、EV ¥200/回（+2.0%） |

定義:

\[
P = EV \times N
\]

合格の主判定は **手数料・スリッページ・レバ手数料等を含む純額** で \(P \ge P^*\)。

### 2.4 取引所・手数料（GMO）

商品（取引所レバレッジ / 暗号資産FX）は検証開始前に1つへ固定する。料金は公式の最新表に従い、仕様書の定数表を更新する。

| コスト項目 | 扱い（初期） |
|---|---|
| 取引手数料 | 商品・銘柄の公式どおり（主要レバは無料の場合あり） |
| レバレッジ手数料 | 建玉評価 × **0.04% / 日**（JST 6:00 またぎ） |
| ロスカット手数料 | 建玉の **0.5%**（発生確率を期待値に含める） |
| 強制決済手数料 | 追証未解消時など、公式どおり |
| API手数料 | 無料（公式記載に従う） |

**設計上の注意**: 取引手数料が無料でも、成行はスリッページ、指値は未約定が実質コスト差になる。手数料差だけで指値優位を断言しない。

## 3. 全体設計（レイヤ）

```
[L0 制約層]  取引所・資金・時間足下限・リスク上限（本章 §2）
     ↓
[L1 機会層]  トレード回数 N の上限・分布
     ↓
[L2 エッジ層] 参加者・bot歪み等に基づくエントリー／決済（本章 §6）
     ↓
[L3 損益層]  EV → 月次 P（執行コスト込み）
```

- L0〜L1は市場・運用ルールで決まりやすい（変更時は再ベースライン）。
- L2がロジック本体（リサーチ対象）。
- L3は採点（検証の合格ライン）。

「勝てる」の定義は、L2の見た目の良さではなく **L0制約下で L3 が \(P^*\) を満たすか**。

## 4. 変数の包含関係

```
月間純利益 P
├── EV（1回あたり期待純損益）
│   ├── グロス損益 G
│   │   ├── 勝率 W
│   │   ├── 平均勝ち幅 Aw
│   │   └── 平均負け幅 Al
│   └── コスト C（1トレード往復の期待コスト）
│       ├── 取引手数料 Fee_trade（Maker/Taker・入口/出口）
│       ├── レバレッジ手数料 Fee_lev
│       ├── スリッページ / スプレッド相当 Slip
│       ├── ロスカット手数料 Fee_LC（稀だが期待値に含める）
│       └── 強制決済・追証シナリオの期待損失
│
└── N（月間トレード回数）
    ├── シグナル発生回数 S
    ├── フィルタ通過率 f
    ├── 約定成功率 fill
    ├── 同時建玉・証拠金制約
    └── 稼働日数・時間帯
```

| 親 | 子 | 関係 |
|---|---|---|
| \(P\) | EV, N | 積 |
| EV | G, C | 差 \(EV = G - C\) |
| G | W, Aw, Al | \(G = W\cdot Aw - (1-W)\cdot Al\) |
| C | Fee_*, Slip, … | 和（期待値） |
| Fee_trade | Maker比率 m, 料率 | 混合 |
| N | S, f, fill, 資金制約 | 積・min |

## 5. 変数の因果関係

```
[市場ボラティリティ・レジーム・参加者構成]
        │
        ├─→ S ──→ N
        └─→ Aw, Al ──→ G ──→ EV ──→ P
                         ↑
[ロジック（エッジ仮説の検知・執行）] ──┤
        │                              │
        ├─→ W, Aw, Al                  │
        ├─→ 保有時間 h ──→ Fee_lev ──→ C
        └─→ 注文方針（指値比率 m）
                    ├─→ Fee_trade / Slip
                    └─→ fill ──→ N

[資金ルール: margin=B/10, Q=B/5, B=¥50,000 初期]
        ├─→ Q ──→ G, C のスケール（複利で B 更新）
        └─→ 同時ポジ上限 ──→ N 上限

[GMO料金表・商品選択]
        └─→ Fee_* の係数
```

### 主要トレードオフ

1. 指値比率 m↑ → コスト改善（EV↑）だが fill↓ → N↓  
2. 保有時間 h↑ → 値幅の余地（G↑）だが Fee_lev・相場リスク↑  
3. フィルタ厳格化 → EV改善の余地だが N↓  
4. N増加だけでは、EVが薄いとコスト負けしやすい  

### N帯と必要エッジ（参考）

| 月間 N | 必要な1回 EV | \(Q\)=¥10,000 比 |
|---|---|---|
| 200 | ¥12.5 | +0.125% |
| **50** | **¥50** | **+0.5%（Gate2 現行）** |
| 20 | ¥125 | +1.25% |

Stretch（Gate 対象外）: N=50 で EV ¥200（+2.0%）→ 月次 +20%（¥10,000）。

薄い EV 帯では、建玉比例コストが「利益のうち何割を持っていくか」が大きくなる。現行は N=50 とし、1回あたりの厚みを優先する。

## 6. エッジ仮説（L2）

### 6.1 仮説の書き方（必須粒度）

次の層が書けない案はバックテストしない。

| 層 | 内容 |
|---|---|
| L1 メカニズム | 誰の・どんな歪みか |
| L2 検知 | 観測可能な定義（数値・条件） |
| L3 執行 | いつ・どう入るか／出るか |
| L4 マネー | 利確・損切・N・同時建玉 |

「上位トレンド＋押し目」のような **形だけの記述は L3 に過ぎず、エッジ説明にならない**。

### 6.2 リサーチプロセス

```
エッジの仮説（L1）
  → 複数の詳細仮説（葉まで数値化）
  → 検証（理論値 / 執行込み）
  → ナレッジ蓄積（採用・棄却理由）
  → 別仮説へ移行
```

パラメータ微調整より、**L1（メカニズム）の乗り換え**を優先する。

### 6.3 時間足ロール（共通）

| 役割 | 足 | 用途 |
|---|---|---|
| 最上位 | 12時間（主）／日足は感度分析 | 大きなレジーム・逆方向の禁止など |
| 大きなトレンド | 1時間（主）／4時間は感度分析 | 波・継続／回帰の文脈 |
| エントリー | 5分（主）／1分は感度分析 | タイミング |

トレンドフォローか回帰（戻り）かは、仮説ごとに検証して良いモデルを採用する。

### 6.4 本命仮説一覧

#### H-A｜清算・損切り連鎖後の吸い戻し（流動性狩り後の回帰）

| 項目 | 内容 |
|---|---|
| メカニズム | 直近高安の外側にストップ／強制決済が溜まり、一掃後にオーバーシュート→短時間で回帰 |
| なぜ残るか | ストップは価格に置かれる構造。連鎖は瞬間的で遅延参加者が不利 |
| 検知 | 5mで直近レンジ突破（例: ≥0.4×ATR）かつ range が中央値の ≥2.5倍 |
| 執行 | ブレイク方向への飛び乗り禁止。突破後、逆方向へ 0.3×ATR 戻した確定で回帰方向へ |
| 決済 | 利確: 突破前レンジミッド or +1.5〜2.5%。損切: 極端値の外側。時間切れ 1〜3h |
| 棄却 | 回帰確率が弱い／突破継続の方が強い（→ H-B） |

#### H-B｜モメンタム点火の早期検出（初期推奨・主検証候補）

| 項目 | 内容 |
|---|---|
| メカニズム | レンジ後の一方向加速。遅い MA クロス勢の前に加速度で入る |
| なぜ残るか | 多くの bot は確定足・長め指標を待つ。点火初期に非対称が残る |
| 検知 | 5mで同方向クローズ k 本連続（例: 3）、実体 ≥ 中央値×1.5、押しが伸びの 30%未満。大逆行レジームでは見送り |
| 執行 | 3本目確定 or 初押し（伸びの 20–40%戻し）。**遅入禁止**: 起点から既に +1.5%以上なら見送り |
| 決済 | 利確 +2.0〜3.5%。損切は点火起点下／上（目安 −0.8〜−1.2%） |
| 棄却 | ノイズ化／遅入禁止を外すとエッジが消える場合は「早期性依存」と記録しルール厳守が必要条件 |

#### H-C｜セッション切替の参加者ギャップ（東京↔欧米）

| 項目 | 内容 |
|---|---|
| メカニズム | 時間帯で参加者・板厚が変わり、遅延追随や薄板フェイクが出る |
| 亜種 | C1: 欧米帯の追随遅れを順方向押しで取る / C2: 東京帯急変は回帰寄り（H-A連携） |
| 棄却 | 時間帯で EV の符号・大きさが説明できない |

#### H-D｜群集インジケータの遅延利用（bot同質性）

| 項目 | 内容 |
|---|---|
| メカニズム | RSI・GC・キリ番等に注文が集中し、到達自体が流動性イベントになる |
| 執行 | 混雑シグナル確定の「次の初押し」のみ。上位と同方向。シグナル足の即成行は禁止 |
| 棄却 | 混雑イベントの有無で成績が変わらない／即成行の方が良い |

#### H-E｜JST 6:00 レバ手数料前後の整理歪み

| 項目 | 内容 |
|---|---|
| メカニズム | 6:00またぎ手数料インセンティブにより、前後でスクエア／ロールが集中 |
| 検知 | JST 5:30–6:30 とその他時間帯の return/range 比較（まず記述統計） |
| 棄却 | 分布に有意差なし |

### 6.5 初期検証順序

1. 記述統計で歪みの有無（トレードなし）: H-A / H-B / H-C / H-E  
2. 有意なものだけ L3 を付け、理論値と執行込みで P を採点  
3. 棄却理由までナレッジ化  
4. 初期推奨: **主 H-B、対照 H-A、探索 H-E**。H-C/H-D は主が立った後のフィルタ候補

## 7. 執行モデル（fill / Slip）

### 7.1 目的

理想約定のみのバックテストは、特に指値戦略で **EV と N を過大評価**する。執行モデルを仮置きし、常に二系統で報告する。

### 7.2 報告ルール（必須）

すべての検証結果は次の **2列** を出す。

| 列 | 意味 |
|---|---|
| **理論値** | シグナルどおり理想約定（検証の上限感） |
| **執行込み** | 仮置き fill/Slip 適用（合格判定の主指標） |

あわせて **執行込み ÷ 理論** の劣化率を記録する。

### 7.3 仮置き（初期値・実測で改定）

| 項目 | 仮ルール |
|---|---|
| 指値エントリー | 価格タッチでも **fill = 70%**。未約定は見送り（追撃成行なし） |
| 成行／逆指値決済 | 100%約定、不利方向 **Slip 0.02%** |
| 利確指値 | タッチで fill = 85%。未達は時間切れ成行（Slip 0.02%） |
| 取引手数料 | 固定した商品の公式料率 |
| レバ手数料 | 6:00またぎ建玉に 0.04%/日 |
| 日またぎ方針（初期） | 仮説により原則スクエアとし、Fee_lev を分離測定しやすくする |

実運用データが取れたら fill/Slip を更新し、同一ロジックを再採点する。

## 8. 検証プロトコル（再現性）

### 8.1 固定して回すもの

- 銘柄: BTC/JPY  
- 資金: ¥50,000 / 証拠金 ¥5,000 / 2x  
- N帯目標: 50  
- 執行仮置き: §7  
- 出力: 理論値と執行込みの両方  

### 8.2 手順

1. L1 仮説を1つ選ぶ（または主＋対照）  
2. 葉（パラメータ）を小さくグリッドする  
3. 学習窓と検証窓を分離（例: 6ヶ月フィット → 次3ヶ月 OOS）  
4. 必須出力: N, W, EV, P, maxDD（両列）、fill 実現率、劣化率  
5. 採用: 複数 OOS で執行込み \(P\) が安定して \(P^*\) に近い、または明確に正の EV  
6. 棄却時は理由をナレッジに残し、次の L1 へ  

### 8.3 合格判定（二層）

#### Research Gate（研究品質 — promote 判定の主指標）

Research Loop の stop/go に使用。**月次 P は最適化目標にしない。**

| 指標 | 基準 |
|---|---|
| 執行込み EV | > 0（VALIDATION 期間） |
| Profit Factor | ≥ 1.15 |
| maxDD | ≤ 15% BR（¥7,500） |
| Walk Forward pass rate | ≥ 60% |
| Monte Carlo p95 DD | ≤ ¥7,500 |
| Monte Carlo ruin prob | ≤ 5% |
| Robustness | fee/slip +20% でも PF ≥ 1.0 |

詳細: [validation-spec.md](research/validation-spec.md)

#### Business Gate（実運用 KPI — Gate1 / Gate2）

| 優先 | 指標 | 基準 |
|---|---|---|
| Gate1 | 執行込み EV + N | EV > 0、N ≈ 50 ± 20% |
| Gate2 | 執行込み月次 P | ≥ \(0.03 \times B\)（初期 ¥1,500） |
| 副 | maxDD、パラメータ感度 | 過学習・脆弱でないこと |
| 参考 | 理論値 | 上限把握用（単独合格にしない） |

#### データ分割

| 名称 | 期間 | 用途 |
|---|---|---|
| TRAIN（IS） | 2024-01 .. 2025-06 | 戦略開発 |
| VALIDATION（OOS1） | 2025-07 .. 2026-02 | パラメータ調整（記録必須） |
| TEST（OOS2） | 2026-03 .. 2026-08 | **最終判定のみ**（ロック） |

#### 評価優先順位

1. OOS（VALIDATION）で期待値が残るか  
2. Walk Forward / Monte Carlo で過学習でないか  
3. DD に対して収益が十分か  
4. Sharpe / PF  
5. 手数料・Slippage 込み  
6. 月次 P（**結果**。Research Loop では最適化しない）
