## 1. なぜ前提を見直すか

BTC 5m algo 検証（2024-01〜2026-08）の結果:

| 事実 | 示唆 |
|---|---|
| Gate2 pass 候補 **ゼロ** | 「ボラが高い＝稼ぎやすい」は誤り |
| H-D canonical: Research Gate pass、Gate2 fail | edge はあるが **L3（月次 P）未到達** |
| H-C2 / H-D4: N 帯構造的未到達 | 稀イベント単体 L1 は不向き |
| 執行劣化 30% 超が常態 | 理論値 pass ≠ 採用可 |

→ **検証パイプラインは資産。市場選択は未確定。**  
独立・不労所得という上位目的に照らし、市場と Gate を分離して設計する。

### 複利の現実チェック

目標金融資産 F、年利 r、年数 n の場合:

\[
F_{future} = F_{now} \times (1+r)^n + \text{（年間追加投入の将来価値）}
\]

| シナリオ | 年利 | ¥50k 起点・10 年 | コメント |
|---|---:|---:|---|
| NISA インデックス | 7% | ≈¥98k（追加なし） | 追加投入が支配的 |
| algo Gate2 相当 | 36%（+3%/月） | ≈¥1.7M | **未証明**・高 DD |
| algo 現実的 upper | 15%/年 | ≈¥202k | Research 合格時のみ |

→ **独立の主エンジンは Layer 1（資産形成）。Layer 2（algo）はオプション。**

## 4. 二層ポートフォリオ（採用方針）

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1 — 資産形成（複利の本体）          配分 70〜90%   │
│   NISA 成長枠 / インデックス / 月次リバランス bot        │
│   目的: 税引後複利・低 DD・独立に直結                    │
└─────────────────────────────────────────────────────────┘
                          ↓ edge 証明時のみ統合
┌─────────────────────────────────────────────────────────┐
│ Layer 2 — algo 研究（オプション）         配分 10〜30%   │
│   検証済みパイプラインで edge 探索                       │
│   現行: BTC 5m（GMO）— hold / Paper 監視のみ             │
│   次候補: 米 ETF 日足 / 日本株スイング                   │
└─────────────────────────────────────────────────────────┘
```

### Layer 1 ルール

| 項目 | 方針 |
|---|---|
| 商品 | 全世界株 / S&P500 / オルカン系 ETF（NISA 成長枠） |
| リバランス | 月 1 回 or 乖離 ±5% |
| 成功指標 | ベンチマーク ±1%/年 以内、DD < 20% |
| bot 化 | 注文 API + リバランスロジック（低頻度） |

### Layer 2 ルール

| 項目 | 方針 |
|---|---|
| 現行 BTC | **tuning 停止**（PM-20260906）。PT-B 月次監視のみ |
| 新規探索 | Gate 未到達なら **市場追加** を優先（同一市場の深掘りより） |
| promote 条件 | [gate-by-market.md](gate-by-market.md) の **Market Gate** pass |
| live 禁止 | Gate2 + 3 ヶ月 forward pass まで |

## 5. 市場選定 — 7 軸評価

詳細スコア: [market-selection-sheet.csv](market-selection-sheet.csv)

| 軸 | 重み | 1 の意味 | 5 の意味 |
|---|---:|---|---|
| A. エッジ発見 | 25% | retail で統計優位ほぼ不可 | 構造歪みが残っている |
| B. コスト後純益 | 20% | コストが edge を消す | 税・手数料後も残る |
| C. 資本効率 | 15% | 少額で始められない | 少額・レバで回転可 |
| D. 自動化 | 15% | API/時間制約が厳しい | 24h・API 安定 |
| E. リスク（独立整合） | 15% | 破綻・大 DD リスク大 | 現物・分散で安定 |
| F. 検証コスト | 5% | データ/API 不足 | 再現 BT が容易 |
| G. 持続性 | 5% | 規制で消える | 制度・市場が安定 |

## 6. Go / No-Go — 市場・戦略の採用判断

| # | チェック | Go | No-Go |
|---|---|---|---|
| 1 | 執行込み OOS で EV > 0（2 split 以上） | ✓ | 単体採用禁止 |
| 2 | Market Gate pass（市場別 N 帯） | ✓ | Gate 見直し or 市場変更 |
| 3 | forward 3 ヶ月 Gate2 再現 | ✓ | live 禁止 |
| 4 | 最大 DD < 許容（§3 記入値） | ✓ | サイズ縮小 |
| 5 | sim vs live fill 差 < 20% | ✓ | 執行モデル修正 |
| 6 | メンテ < 月 5h | ✓ | 自動化 or 停止 |
| 7 | Layer 2 配分内 | ✓ | 本体資金に触れない |
