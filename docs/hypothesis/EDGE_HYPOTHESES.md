方針: **価格だけで作れる形はもう一巡した**（SPOT-001 で51本 / 4H系で41本が不合格）。

## 0. なぜ方向転換するのか

これまでの失敗は偶然ではありません。

| 事実 | 意味 |
|------|------|
| ダブルボトム51本・4H系41本すべて不合格 | OHLCVだけの形は **誰でも同じものを作れる** → 先に取られている |
| Set B PASS が Set C で反転 | 薄いエッジは期間依存。構造的な理由がない |
| 4Hは EV 厚いが n 不足 / 15m は n 足りるが費用負け | 価格だけでは「質×回数」を同時に満たせない |

**歪みの本体は「誰が、どちら側に、どれだけ無理をして乗っているか」**。  
それは価格ではなく **建玉（OI）・資金調達率・現物先物のズレ・成行の偏り** に出ます。

### 使えるようになったデータ（全期間の入手を確認済み）

| データ | 内容 | 解像度 | Set A/B/C |
|--------|------|--------|-----------|
| `metrics` | 建玉(OI)、上位トレーダー長短比、全口座長短比、**成行買売比** | 5分 | すべて取得可 |
| `fundingRate` | 資金調達率 | 8時間 | すべて取得可 |
| `premiumIndexKlines` | **先物プレミアム**（perp − index） | 1時間 | すべて取得可 |
| 先物 klines | perp の OHLCV + 成行買い出来高 | 15分〜 | すべて取得可 |
| 現物 klines（既存） | spot の OHLCV | 15分〜 | 取得済 |

取得元は Binance の公開アーカイブ。**清算スナップショットは配布終了**のため、清算は「OIの急減」で代理します。

## EH-01

### 建玉が増える突破だけが本物

**CLAIM:** N日高値の突破は、同時に **建玉（OI）が増えている**ときだけ継続する。建玉が減りながらの突破は「売り方の焼き（買い戻し）」なので戻る。安値側は対称。

**なぜ市場が織り込めていないか:**  
価格チャートには「新規の資金が入った突破」と「既存ポジションの解消で上がった突破」の区別が **一切出ません**。同じ形の陽線に見えます。区別できるのは建玉の増減だけで、価格だけを見ている bot は両方を同じ扱いで撃ちます。

**誰が損するか:** 突破の形だけで飛び乗る参加者（過去の自分たちの L-BREAK 含む）。焼かれた売り方の買い戻しが終わると、支える買いがないので落ちます。

**TESTABLE:** 突破を「OI増加あり / なし」で二分し、**その後のリターン分布が有意に違う**こと。増加側のみで費用後 EV > 0。

**棄却条件:** OI 増減で分けても分布が同じ。または増加側だけでも費用後 EV ≤ 0。

**実装の1点:** 既存の Donchian 突破に **OI増減フィルタのみ**を足す（他は変えない）。L-BREAK と直接比較できる。

## EH-02

### 現物が先に動いた時だけ乗る

**CLAIM:** 同じ15分足で **現物のリターンが先物のリターンを上回る**とき、その動きは現金の買いが主導しており、続きやすい。逆に先物だけが動いている動きは続かない。下方向も対称。

**なぜ市場が織り込めていないか:**  
これは春希さんの言う「市場がトレンドに気づく前に検知する」に最も近い形です。先物だけを見ている参加者（大多数の bot）には、いま動かしているのが **現物の買い手なのかレバの買い手なのか** が見えません。現物主導は資金の裏付けがあるため持続し、レバ主導は資金調達コストと清算で自壊します。

**誰が損するか:** 先物のチャートだけを見て順張りする参加者。レバ主導の動きに乗って清算される側。

**TESTABLE:** 15分足ごとに（現物リターン − 先物リターン）を計算し、この値の上位帯でのみエントリーした場合、費用後 EV > 0 かつ n ≥ 100。

**棄却条件:** 差分でグループ分けしても先行リターンが変わらない。差が費用（往復0.15%級）より小さい。

**実装の1点:** 既存の突破/押し目の入口に **spot−perp 乖離ゲート**のみを追加。

**注意:** 現物は Binance、先物も Binance で揃える（取引所を混ぜない）。本番の Bybit へは移植時に再確認。

## EH-03

### プレミアム先行の上昇は続かない

**CLAIM:** 先物プレミアム（perp − index）が直近N日レンジの上端に張り付いているのに、現物側の上昇が伴っていないとき、その上昇はレバだけで押し上げられており **ショートが取れる**。

**なぜ市場が織り込めていないか:**  
プレミアムは「レバ買い需要の値段」です。プレミアムが高い＝みんなが高いコストを払って強気になっている状態で、価格が上がるほど脆くなります。しかし価格チャートには「この上昇がいくらのコストで買われているか」が出ません。

**誰が損するか:** 高いプレミアムを払って上を追う側。ここが清算の燃料になります。

**TESTABLE:** プレミアム上位帯 × 現物同時上昇なし、の条件でショートしたときの費用後 EV > 0。DD ≤ 20%。

**棄却条件:** プレミアム高値帯でも下落しない（トレンド中は高プレミアムが長く続く、という既知の反例が支配的）。

**実装の1点:** 逆張りショートは危険なので、**価格の失速確認（直近高値を更新できない）を必須**にした上で1点だけ。

## EH-04

### 保有コストが安いトレンドだけ伸びる

**CLAIM:** 同じ上昇トレンドでも、**資金調達率が低い（またはマイナス＝受け取れる）局面**のトレンドは長く伸び、資金調達率が高い局面のトレンドは短命。ショート側は符号を反転。

**なぜ市場が織り込めていないか:**  
「資金調達が極端＝反転」という単純な話ではありません。ここで見るのは **トレンドの寿命に対するコストの非対称性** です。混み合っていない（コストが安い）方向のトレンドは、資金調達の出血がないため保有し続けられ、テールの大勝ちを取れます。トレンドの形だけを見ている bot はこの差を持ちません。

**誰が損するか:** 混み合った高コスト側で長く持ち、資金調達と清算で削られる参加者。

**TESTABLE:** 同一トレンドロジックを資金調達の高/低で二分し、**低コスト側のみ**で費用後 EV > 0。資金調達を損益に必ず計上する。

**棄却条件:** 資金調達を損益に入れても二群の差が出ない。

**実装の前提:** バックテスト側に **funding の計上を実装する必要あり**（現状は fee+slip のみ）。これは EH-04 と EH-10 の前提工事。

## EH-05

### 建玉の山＋高値更新失敗は落ちる

**CLAIM:** 建玉が直近N日の高水準にあり、かつ **価格がk本以内に高値を更新できず**、上位トレーダーの長短比が買いに偏っているとき、下方向に落ちやすい（ショート）。

**なぜ市場が織り込めていないか:**  
これは「下に清算の燃料がどれだけ積まれているか」を見る仮説です。価格は横ばいに見えても、その下に積まれたロングの量は価格に出ません。燃料が多いほど、少しの下落が連鎖を起こします。

**誰が損するか:** 高値圏で建玉を積んだ高レバのロング。

**TESTABLE:** 条件成立後の下方向リターンが、無条件の同期間分布より有意に悪い。ショートで費用後 EV > 0。

**棄却条件:** 建玉が高いまま価格が上がり続けるケースが支配的（トレンド相場での逆張り死）。→ 高値更新失敗の確認を必須にして回避を図る。

**実装の1点:** 「建玉高水準」の定義のみをノブにする。

## EH-06

### 個人と上位が逆を向いたら上位側

**CLAIM:** 全口座の長短比（個人が多数）が強く買いに偏っている一方、上位トレーダーの長短比が売りに傾いているとき、**上位側に付く**（この例ではショート）。逆パターンではロング。

**なぜ市場が織り込めていないか:**  
この2つの比率は公開されていますが、**多数側と資金量側のズレ**として使っている参加者は少数です。多数の小口が逆側にいる状態は、清算連鎖の起点になりやすい。

**誰が損するか:** 多数側に張った小口。

**TESTABLE:** 乖離が大きい上位帯のみでの費用後 EV > 0、n ≥ 100。

**棄却条件:** 乖離の符号と先行リターンが無相関。または乖離が大きい局面が年に数回しかない。

**注意:** この比率は **Binance の参加者構成**であり、市場全体ではありません。翻訳の弱点として明記します。

## EH-07

### 建玉が吹き飛んだ直後は元の方向に戻る

**CLAIM:** 短時間で **建玉が急減**し（清算の代理指標）、同時に値幅の大きい足が出たあと、ポジションが洗われているため **急変前のトレンド方向へ戻りやすい**。

**なぜ市場が織り込めていないか:**  
清算カスケードの「初動」は個人には取れません（速度勝負）。取れるのは **終わったあと**です。終わったかどうかを判定できるのは建玉の減り方で、価格の長い髭だけでは「まだ続くのか終わったのか」が分かりません。

**誰が損するか:** 清算に巻き込まれて強制的に降ろされた側。彼らが消えたあと、板が薄いまま元の方向に戻ります。

**TESTABLE:** OI急減イベント後の、急変前トレンド方向のリターン中央値が費用後プラス。

**棄却条件:** 遅れて入ると費用後の中央値がゼロ以下。イベント数が年10回未満。

## EH-08

### 静かなのに建玉が増える＝仕込み

**CLAIM:** ボラティリティが縮小している（値動きが静か）のに **建玉が継続的に増えている**期間のあとのブレイクは、通常のブレイクより大きく伸びる。方向はブレイク側に従う。

**なぜ市場が織り込めていないか:**  
まさに「市場がトレンドに気づく前の検知」です。価格が動いていない間に建玉だけが積まれるのは、**誰かが静かに仕込んでいる**状態。価格だけを見ていると「ただのレンジ」に見えます。

**誰が損するか:** レンジと判断して逆張りしていた参加者。ブレイク時に一斉に踏まれます。

**TESTABLE:** 「圧縮＋OI増」後のブレイクと「圧縮のみ」後のブレイクで、その後の伸び（および費用後EV）が有意に違う。

**棄却条件:** 二群に差がない。または該当イベントが年10回未満。

---

## EH-09

### 高値更新しても成行買いが減る＝吸収

**CLAIM:** 価格が高値を更新しているのに、**成行買い比率が上昇レッグを通じて低下**しているとき、買いは受動的な売り手に吸収されており反転しやすい（ショート）。

**なぜ市場が織り込めていないか:**  
これは板の中身に近い情報です。「上がっているのに買いの勢いが弱まっている」というズレは価格には出ません。出来高だけを見ても、それが買い主導か売り主導かは分かりません。

**誰が損するか:** 高値更新を見て順張りする参加者。

**TESTABLE:** 価格の高値更新 × 成行買い比率の下降トレンド、の条件でショートして費用後 EV > 0。

**棄却条件:** 成行比率の傾きと先行リターンが無相関。強いトレンドで踏み上げられて DD 超過。

## EH-10

### 資金調達がリセットされた継続は本物

**CLAIM:** 上昇が続いたあと、**資金調達率が平常水準まで戻り**（＝混み合いが解消）、それでも価格が構造を維持しているなら、トレンドは再開する。ショート側は対称。

**なぜ市場が織り込めていないか:**  
価格の「押し目」は誰にでも見えますが、その押し目で **混み合いが解消されたのか、まだ混んでいるのか** は資金調達にしか出ません。同じ形の押し目でも、コストが抜けた押し目のほうが安全に持てます。

**誰が損するか:** 混み合ったままの押し目を買って、次の下落で清算される側。

**TESTABLE:** 押し目継続ロジックを「資金調達リセット済 / 未」で二分し、リセット側のみで費用後 EV > 0。

**棄却条件:** 二群に差がない。

## 2. 次にやること

優先順は「機構が再現した × EVを上げる余地がある」で決めます。**採用ではなく改良**の段階です。

1. **EH-01 を軸にする。** 入口ではなく **退出と建て方**を変える（現在は突破即エントリー・ATRトレール）
2. **EH-09 を EH-01 のフィルタにしない。** 積むのは禁止。別ロジックとして測る
3. **EH-07 の入り方を作り直す。** 方向は正しいので、遅延と損切幅だけを変えた新カード
4. **EH-02 は測り方を再設計する。** 閾値調整では発火数が足りない。仮説自体は保持
5. **EH-03 / EH-04 / EH-05 / EH-08(OI蓄積) は再探索しない**

### 完了した前提工事

1. **データ取得** — `src/autotrade/data/binance_derivatives.py`
2. **funding の損益計上** — engine が `funding_pay_rate` 列を建玉に課金（100本すべて計上済み）
3. **時刻整合** — OI 5分は `[t, t+15m)` で集約、funding は確定済みのみ、premium は1時間ずらし

### 共通ルール（これまでの失敗から）

1. **ノブは1点だけ。** フィルタの積み重ねは DB-21 で失敗済み
2. **各仮説に対照を必ず入れる。** フィルタ除去版と符号反転版。合否ではなく差を読む
3. **Set B PASS だけでは採用しない。** 必ず Set C holdout
4. **n<30 は判定不能と書く。** EV+でも n=7 なら何も言えない
5. `min_trades=100` は **Set B（1年）の合計**
6. **EMA は使わない**、足は **15分以上**
7. 合成データで合否を出さない
8. 建玉・長短比は **Binance の参加者構成**。Bybit 本番前に再確認する

### 正直なリスク

- positioning データは Binance のもの。Bybit の建玉構成とは一致しません
- 「OIが増えた突破は伸びる」は広く語られる話でもあり、**すでに一部織り込まれている可能性**があります。だから EH-01 は「語り」ではなく **二群の差**として検証しました（差は再現）
- 清算スナップショットが無いため、EH-07 は OI 急減の代理。精度は落ちます
- 両期間PASSした2本のEVは +0.008〜+0.038/トレード。**ゼロと区別できません**
