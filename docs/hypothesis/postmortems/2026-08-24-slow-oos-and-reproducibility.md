# SH-01 の宣言外追試と、再現性が壊れていた話

date: 2026-08-24
対象: SH-01 / SH-01N（低速トレンド継続）
関連: [SH-01 postmortem](./2026-08-23-slow-sh01.md) · [SLOW_HYPOTHESES](../SLOW_HYPOTHESES.md)

## 結論を先に

1. **`sh01_tp_4atr` の周辺は点ではなく面だった。** 中心の周り14本を回して、
   Set A 13本・Set B 13本・Set C 12本がゲート通過。42通り（14本×3期間）すべてで EV プラス。
2. **宣言外の4銘柄では、直近期間でエッジが消える。** Set A は全14本プラス（EV +0.26〜+1.36）、
   Set B は減衰、Set C は14本中11本がマイナス。**宣言バスケットには無い劣化。**
3. **2026-08-23 以前の数値は再現しない。** VM を作り直したら、sha256 が一致する入力データに対して
   23本中11本が別の結果になった。原因を追い切り、環境を固定して全期間を取り直した。
   **SH-01 の結論は変わらない**（`tp_4atr` は3期間PASSのまま、EV はむしろ改善）。

---

## 1. 近傍は面だった

`sh01_tp_4atr` は3期間ゲートを通った唯一の設定でしたが、系統内で EV が最も低い設定でもあり、
「ゲートがたまたま気に入った点」の疑いがありました。利確・入口・退出・損切りを中心の周りで
振って確かめます。

| | Set A | Set B | Set C |
|---|---|---|---|
| ゲート通過 | 13/14 | 13/14 | 12/14 |
| EV プラス | 14/14 | 14/14 | 14/14 |

中心 `sh01n_center` は +0.706 / +0.619 / +0.671。落ちるのは利確を近づけた `tp_2`（+0.07/+0.31/+0.05）
だけで、これは「勝ちを早く切ると死ぬ」というこれまでの学びと同じ向きです。
**一点でしか立たない結果ではありませんでした。**

買い持ちとの比較（Set C、等加重）:

| | 戦略 | 買い持ち |
|---|---|---|
| リターン | +43.4%（中心） | **-33.1%** |
| 最大DD | 17.0% | 64.2% |

14本すべてが買い持ちを上回ります。下げ相場でプラスなので、単なるロングβではありません。

## 2. 宣言外バスケットでは直近が消える

`configs/eval_v2_oos.yaml` に LTC / DOT / AVAX / LINK を宣言しました。
「時価総額上位で全期間データがある」だけで機械的に選び、**SH-01 の結果を見る前に**確定しています。

| | Set A | Set B | Set C |
|---|---|---|---|
| 宣言6銘柄 EV（中心） | +0.706 | +0.619 | +0.671 |
| 宣言外4銘柄 EV（中心） | **+1.202** | +0.464 | **-0.090** |
| 宣言外で EV プラス | 14/14 | 11/14 | 3/14 |

n が 100 に届かない期間があるためゲート判定は割り引いて読む必要がありますが（4銘柄なので
6銘柄前提の `min_trades=100` は構造的に不利）、**読むべきは符号**で、そこははっきりしています。

同じ期間・同じロジックで銘柄だけ替えると Set C が +0.671 から -0.090 になる。
**エッジは銘柄に依存しています。**

内訳を見ると理由が見えます。

| Set C 中心 | ロング | ショート |
|---|---|---|
| 宣言6銘柄 | n=105 EV +0.739 | n=89 EV +0.590 |
| 宣言外4銘柄 | n=59 EV **-0.324** | n=64 EV +0.126 |

崩れているのはロング側だけです。Set C の買い持ちは主要6銘柄が -33.1%、
宣言外4銘柄が **-64.2%**。2軍アルトは「下げ続けただけで、上に走る局面が無かった」。
トレンド追随は走る対象が要るので、走らない銘柄群では原理的に稼げません。

**この解釈は後付けです。** 事前に予測していません。事実として言えるのはここまで:

- 宣言バスケット（事前宣言済み）での3期間PASSは有効な結果である
- **その結果を宣言外の銘柄に広げてはいけない。実測で否定されている**

なお宣言外でも買い持ち（-64.2%）は14本すべてが上回っています。負けてはいませんが、
ゼロ付近であって、採用の根拠にはなりません。

## 3. 再現性が壊れていた

### 何が起きたか

VM が作り直され、gitignore 対象のデータキャッシュと Python パッケージが消えました。
全部取り直して同じ検証を回したところ、**23本中11本が 08-23 と違う数字**を出しました。

| logic | n（旧→新） | EV（旧→新） |
|---|---|---|
| `sh01_tp_4atr` | 133 → 126 | +0.731 → +0.706 |
| `sh01_regime_200d` | 68 → 68 | +2.081 → +1.821 |
| `sh01_trail_4` | 84 → 83 | +2.655 → +2.721 |
| `sh01_stop_1atr` | 101 → 98 | +2.539 → +2.668 |

`sh01_base` を含む12本は小数点以下まで完全一致します。ズレるのは Set A と Set C で**同じ6本**
（＋ veto 系）でした。ランダムではありません。

### 潰した仮説

| 疑い | 検証 | 結果 |
|---|---|---|
| pandas のバージョン | 2.2.3 と 3.0.5 で実行 | 同一。シロ |
| 浮動小数点の同値判定 | 全価格に 1e-6 の擾乱を6シード | n 完全一致、EV 差 0.001。**シロ** |
| コードが変わった | ffca59d を worktree に取り出して現データで実行 | 現在と同じ数字。シロ |
| 入力データが違う | lock の sha256 照合 | OHLCV は全一致。metrics のみ差分 |

`tp_4atr` は derivatives を使いません。**sha256 が一致する入力で結果が変わっている**、
という状態でした。残る説明は「08-23 の実行が、コミットされた lock とは別のバイト列を
読んでいた」（lock を実行後に再生成した等）。

### 直したこと

lock は入力を固定していましたが、**それを読む側は何も固定していませんでした**。

- `requirements.lock.txt` — numpy / pandas を含む実行環境の完全固定
- レポートに実行環境（python / pandas / numpy）と **検証した lock の sha256** を記録
- `scripts/jitter_sensitivity.py` — 微小擾乱に対する感度を測る反証テスト

これで次に同じことが起きたら、推測ではなく差分として見えます。

### 取得側のバグも1件

同じ調査中に、metrics だけハッシュが変わる理由が判明しました。日次アーカイブの 404 を
そのまま信じてその日を捨てていたため、**混雑で落ちた日と、取引所がそもそも公開していない日が
区別できていません**でした。フレームが黙って短くなるだけです。

404 / 429 / 5xx をリトライし、本当に無いアーカイブは件数を数えて表示するようにしました。
再取得で同じ sha256 が出ることを確認済みです。Set B / C は欠損ゼロになり、Set A に残る
4日はアーカイブ開始前の実在しない日でした。

### 結論への影響

**ありません。** 環境を固定して3期間を取り直した結果、`sh01_tp_4atr` は3期間PASSのままで、
EV は +0.731 / +0.595 / +0.537 → **+0.706 / +0.619 / +0.671** と改善しています。
2026-08-23 以前の数値は破棄し、以後は 08-24 の再実行を正とします。

## 4. 次

近傍も反証も通り、宣言バスケットでは3期間立っています。ここから先、同じ3期間で
バックテストを足しても、選択圧が増えるだけで証拠は増えません。

判断が要るのは「宣言外で直近が消える」をどう扱うかです。

- **A. 宣言バスケット限定で先に進む** — 銘柄依存を仕様として受け入れ、
  主要6銘柄のみで運用する。次は紙トレードで前向きに測る
- **B. 銘柄選択そのものを検証対象にする** — 「走る銘柄が要る」なら、
  出来高・ボラの事前フィルタを1ノブとして足し、宣言外でも復活するかを見る
- **C. 打ち止め** — 銘柄依存が強すぎるとみなす

推奨は **A**。3期間・6銘柄・反証・近傍・買い持ち比較をすべて通ったものは
プロジェクトで初めてで、これ以上同じデータを叩いても精度は上がりません。
B は魅力的ですが、宣言外の結果を見たあとにフィルタを設計することになるため、
やるなら**別バスケットをもう一組宣言してから**にすべきです。
