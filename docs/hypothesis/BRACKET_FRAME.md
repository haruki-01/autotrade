## なぜこの枠が良いか

**判定基準が理論から出ます。** ドリフトのない価格に対する 1:RR ブラケットの
当たり率は、幅の比だけで決まります。

```
P(利確が先) = 1 / (1 + RR)
```

1:1.5 なら 40%。勝率がそこなら情報ゼロと即断できます。
値幅・RR・保有上限が全条件で共通なので、条件ごとに変わるのは「いつ入るか」
「どちら向きか」だけ。one-point change が構造的に守られます。

頻度も制約ではありません。保有上限6時間・平均保有3.3時間なので、
1枠でも月200回以上撃てます。

## 変数は3つ、順番に決まる

```
帰無     w0 = 1 / (1 + RR)
損益分岐 w* = (1 + c/s) / (1 + RR)     c = 往復コスト率, s = 損切り幅
必要上振れ(pt)  = (c/s) / (1 + RR)
必要上振れ(倍率) = 1 + c/s               ← RR に依存しない。幅だけで決まる
```

シグナルが確率をどれだけ動かせるかは、小さいドリフト μ で展開すると

```
θ ≥ 2c / (s² · RR)                     θ = 2μ/σ²
```

**必要なシグナル強度は幅の2乗と RR に反比例します。** 幅を広げるほうが効く。
ただし6時間の値動きの標準偏差（15分足ATR × √24 ≈ 1.35%）を損切り+利確の
合計が超えると、ブラケットは届かず「6時間で成行決済」になります。

```
損切り × (1 + RR) ≲ 1.35%              ブラケットが機能する条件
```

RR を上げると幅を狭めねばならず、コスト比が悪化します。
これが RR を無限に上げられない理由です。

## 指値にしたときのコスト

入口は指値（メイカー）、利確も指値で置ける（メイカー）、
**損切りだけは成行にせざるを得ません**（指値だと急落で約定しない）。
スリッページもテイカー側の脚にだけ乗せます。

メイカー 0.020% / テイカー 0.055% / スリッページ 0.020%。
1:1.5 なら出口の約60%が損切り側なので、往復 **0.0730%**
（両側テイカーなら 0.150%。約半減）。

### 指値で増えるリスク（実測）

| リスク | 実測 | 損か |
|---|---|---|
| 未約定 | 現値・1本待ちで **1%** | 機会損失のみ |
| 逆選択 | 有利側に置いて約定率77%まで落としても勝率は下がらない（平均 **+0.7pt**） | **観測されず** |
| 遅延 | 平均1本（15分） | 決済率がわずかに落ちる |

手数料の節約は勝率 4.4pt 分の価値。実測の劣化はゼロなので、
**指値にして損はありません。** ただしこの計測は「足の中で触れたら約定」
という仮定。実運用ではキュー位置で約定率は悪化する方向です。

funding は平均保有3.3時間で 1トレードあたり約0.004%。往復コストの6%で、
判断を変える大きさではありません。

## 保有を 12時間 / 16時間に延ばすか

必要上振れは幅だけで決まり、上限時間には依存しない。
延ばす意味は **同じ決済率70%のまま幅を広げられる** こと。

| 上限 | 6h 値動きσ | 70%を満たす最大損切り | 利確 | 必要上振れ |
|---|---|---|---|---|
| 6h（旧） | 1.57% | 0.70% | 1.05% | **+4.2pt** |
| 12h（現行） | 2.21% | 1.00% | 1.50% | **+2.9pt** |
| 16h | 2.57% | 1.20% | 1.80% | **+2.4pt** |

6→12h で必要が 1.3pt 減る。12→16h はさらに 0.5pt。収穫は12h側が大きい。
同じ幅（0.70%）のまま延ばすと決済率は 71% → 86% → 91% に上がるが、
必要上振れは下がらない。

1枠のまま延ばしても、建玉中に捨てる割合は **48% → 50% → 51%**。
シグナルが固まるので、上限を倍にしても捨て率はほとんど増えない。
`br_runs_5` は月59回取れており、半分捨てても月50はまだ足りる。

## 1口座で複数ポジションは可能か

**独立したチケット（別の平均単価・別の清算価格）は、サブ口座なしでは持てない。**
本番先 Bybit の USDT 無期限:

| モード | 取引所が見るもの |
|---|---|
| one-way（既定） | 銘柄あたりネット **1本**。逆方向は既存を減らす／反転する |
| hedge | **long 1本 + short 1本** まで。3本目は無い |

近づける手段は Partial TP/SL（数量ごとの利確・損切りペアを複数置く）。
これは独立ポジションではなく、ネット1本の上の条件付き注文。

`br_runs_5` の重なりは **同方向が 86〜89%**。だから hedge（逆方向を同時に持つ）は
捨て率を 48% → 44% にしか落とさない。効くのは「同方向に足す」で、捨て率は **8%**。

春希さんの懸念への答え:

- **利確・損切りがややこしくなる** — その通り。ネットの清算価格は1つ。
  同方向に足すほど清算が近づく。Full モードの損切りは全ロットを一気に閉じる。
  1ロットの決済で取引所が残注文の数量を変えることがある。
- **処理が増えて遅延する** — CPU ではない。部分約定のあとの cancel/replace のレース
  とレート制限が本体。往復 50〜200ms × 本数。足の判定自体は遅れない。
- その他: funding はネット残高、平均単価がロット想定とずれる、ボット停止時に
  仮想ロットの記憶が消える、同方向の足し増しは相関するので回数≠独立情報。

推奨は **1枠のまま 12h に延ばして幅を広げる**。複数建玉は枠が黒字になってから。

## 1分足入口の遅延

測った遅れ（値動きがある2週間、2024-03）:

| 遅れ | 勝率の差 |
|---|---|
| 1〜5分 | **0.0〜0.1pt**（ノイズ） |
| 15分 | −0.5pt |

損切り 1.00% はこの枠では1分 ATR の何十本分なので、発注の遅れは効かない。
1分足にする意味はタイミング精度ではなく、**シグナルの定義を細かくできること**。

効くリスクは遅延ではなく運用:

1. **未完成の足で判断しない**（先読み。本番乖離の主因）
2. 欠けた1分はスキップ（ゼロ埋め禁止）
3. 1分で入って15分足で管理すると、その15分足が入口より前を含み先読みになる
4. 本番クライアントはいま 15m / 4h / 1d しか取らない。1分足なら取得の追加が先
5. 検証は15倍重い（8年で約400万本）。本番の常駐は直近N分なので別問題
