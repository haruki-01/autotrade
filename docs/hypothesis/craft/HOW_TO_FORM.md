# 仮説の立て方（How to form）

## 1仮説の骨格（必須4点）

1. **主歪み** — E1〜E8 のどれか1つ（副フィルタは後）
2. **負ける側** — 誰の強制・癖・費用を取るか（1文）
3. **捕捉ルール** — 最小の観測可能な条件（インジ名ではなく現象）
4. **棄却条件** — 何が数値で出たら捨てるか（先に書く）

例（良い）:
> E1。日足高値更新後に追随する群衆フローを取る。  
> ルール: 前日20日高値抜け確定後のみロング。退出は10日安値割れ。  
> 棄却: コスト後EV≤0、または利益の80%が単月。

例（悪い）:
> EMAとRSIとBBが揃ったら買う。パラメータは後でBTで決める。

## 生成プロンプト（自分用）

次を埋めるまで実装しない:

```text
歪みID:
メカニズム（なぜズレるか）:
負ける側:
個人が取れる理由（レイテンシ以外）:
必要データ:
最小ルール:
費用が殺すポイント:
棄却条件:
既存FAILとの差分（1点）:
```

## 精度を上げる順序

1. メカニズム（文章）
2. 証拠（レバなし統計）→ `evidence/`
3. 最小ルール
4. 費用込み formal eval
5. 学び → `postmortems/`

**順序を飛ばすと、またインジBTになる。**

## AIの使い方

| 使ってよい | 使ってはいけない |
|------------|------------------|
| 歪み文献の整理・棄却理由のレビュー | 特徴量の大量探索 |
| チェックリスト照合 | 「勝ちそうなパラメータ」提案を採用根拠にする |
| 敗因の構造化 | Set B 結果を見て同期間を再最適化 |
