# トレードスポット仮説の考え方（①の作り方）

**ここが「筋のいい仮説」の本体。**  
規律フロー（CREATION/VALIDATION）とは別。先にスポットを考え、あとでロジックと検証に落とす。

---

## 1. スポット仮説とは何か

チャートやフロー上の **くり返し起きうる場面** について、

> 「この形のあと、価格はこう動きやすい」

と言い切れる主張。

あなたの例が原型:

> ダブルボトムのあとネックラインを突破し、ネック近くで再度反発するとロングに伸びやすい

要素分解:

| 部品 | 例 |
|------|-----|
| 事前構造 | ダブルボトム |
| 確認 | ネックライン突破 |
| トリガー | ネック付近への戻りからの再反発 |
| 方向 | ロングに伸びやすい |
| 無効化 | ネックを明確に割り込む、ダブルボトム否定 など |

---

## 2. 筋のいいスポット仮説の条件

| # | 条件 | なぜ |
|---|------|------|
| 1 | **目で見て説明できる** | 実装前に「何を取りに行くか」が共有できる |
| 2 | **入る場所が狭い** | 毎日ある形は費用に負ける（過回転） |
| 3 | **伸び／戻りに非対称がある** | 小さく負けて大きく伸びる余地 |
| 4 | **崩れたらやめられる** | 無効化条件がある |
| 5 | **ロジックを複数書ける** | ①が健全なら測り方②が2つ以上出る |

「インジが揃った」はスポットではない。スポットは **相場の場面**。

## 3. スポット仮説の発想源（本当のストックの増やし方）

規律A〜Nではなく、**場面**から増やす。作り方は2系統:

| 系統 | 文書 |
|------|------|
| A. 演繹・深い複合（見落とし攻め） | [DEEP_COMPOSITE_SPOTS.md](./DEEP_COMPOSITE_SPOTS.md) |
| B. 帰納・データ逆算 | [REVERSE_DISCOVERY.md](./REVERSE_DISCOVERY.md) |

浅い地図: [../spots/CATALOG.md](../spots/CATALOG.md)

### 3.1 クラシックなチャート構造（形）

例（ロング寄り）:

- ダブルボトム → ネック突破 → ネック再テスト反発  
- 押し安値割れず → 戻り高値更新で追随  
- レンジ上抜け → レンジ上端の再テスト支え  
- 上昇旗面（フラッグ）の上抜け  
- 高値切り上げ＋押しの浅さ継続  

例（ショート／慎重）:

- ダブルトップ対称  
- レンジ下抜け後の戻り売り  
- 上昇後のクライマックス＋長い上ヒゲ連発（要・無効化厳しめ）  

### 3.2 トレンド中の「押し目の質」

- 深い押しは失敗しやすい／浅い押しは継続しやすい、等  
- 「押し目買い」一般ではなく、**どの押しが良いか**まで書く  

### 3.3 ブレイクの種類

- 初めての上抜け vs 再ブレイク  
- 出来高を伴うブレイク vs 薄いブレイク（データがあれば）  
- ブレイク失敗（フェイク）後の逆方向  

### 3.4 セッション・カレンダー場面

- ロンドンオープン前後のレンジ解消  
- NY前のアジアレンジ上抜け  
（方向は弱く、ゲート仮説になりやすい）  

### 3.5 フロー・イベント場面（データ前提）

- 清算スパイク確認後の継続  
- 極端fundingのあとの失速→反転（単独禁止・複合）  

### 3.6 自分のチャート観察ログ

週にN枚スクショし、「伸びた／死んだ」をタグ付け → 繰り返す形だけ仮説化。  
**これが最も実務的なストック源。**

## 4. 書き方テンプレ（①専用）

```markdown
# SPOT-XXX: （短い名前）

## 仮説（一文）
（形）のあと、（トリガー）すると、（方向）に伸びやすい。

## 構造
- 事前:
- 確認:
- トリガー:
- 無効化:

## なぜそうなりそうか（任意・短く）
- 誰が慌てていそうか / どこで損切が溜まりそうか

## 実装ロジック案（②・まだ検証しない）
### 実証①
- 使う足:
- 構造の定義（インジ or 価格条件）:
- トリガー定義:
- 退出の考え方:

### 実証②
- （別の測り方）

## まだやらないこと
- formal eval（③）は ready な実証ロジックができてから
```

---

## 5. ① → ② → ③ の進め方

1. **SPOT を先にストック**（本ファイルの発想源）  
2. 各 SPOT に **実証ロジックを2案**書く（インジはここで登場）  
3. 規律チェック（自由度・Who loses・既存FAIL回避）は②のとき  
4. ③検証はロジック単位（formal eval）  
5. ①が弱いのに②を量産しない。②が全部死んだら①を見直すか捨てる  

---

## 6. ダブルボトム例の置き方（見本）

| 層 | 中身 |
|----|------|
| ① SPOT | ダブルボトム＋ネック突破＋ネック再反発 → ロング伸長 |
| ② 実証① | スイング安値2点の公差、ネック＝中間高値、再テスト＝ネック±X%、反発＝陽線 or 短期MA支え |
| ② 実証② | ピボット／ZigZag相当でボトム検知、ネック突破は終値、再反発は4H確認 |
| ③ | 各実証を Set B formal eval |
