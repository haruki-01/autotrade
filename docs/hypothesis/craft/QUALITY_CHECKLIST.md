# 実装前チェックリスト（仮説品質ゲート）

すべて ✅ になるまで `docs/workstreams/` に上げない・コードを書かない。

## A. メカニズム

- [ ] 主歪み ID が1つに定まっている（E1〜E8）
- [ ] 「誰が損するか」が1文で書ける
- [ ] インジは道具として書かれ、歪みそのものになっていない
- [ ] `MARKET_EDGE_MAP` の「やらない戦場」に抵触しない

## B. 証拠

- [ ] `evidence/` に関連メモがある、または「今回は証拠タスクが本体」と明記
- [ ] レバなしで歪みの方向/裾が議論できる（なければ証拠タスクを先にやる）
- [ ] 往復コスト（約0.15%級＋α）より大きいエッジの物語がある

## C. ルール

- [ ] 最小ルール（パラメータ山なし）
- [ ] 変更点が既存ロジックから **1点だけ**（比較可能）
- [ ] 棄却条件が数値で先書きされている
- [ ] 必要データが揃っている（不足なら status=`blocked`）

## D. 検証設計

- [ ] Formal eval（`eval_v1`）で測る前提
- [ ] Set B を見て同期間を再最適化しないと明記
- [ ] 試行として research に残す前提（多重検定を意識）

## 不合格時

inventory カードに `status: draft` または `blocked` のまま残し、足りない項目だけ埋める。
