## 0. なぜ時間軸を変えるのか

これまでの217本は、シグナルの良し悪し以前にコストで負けていました。

| 足 | ATR中央値（終値比） | 損切1.5ATR に対するコスト比 |
|-----|--------------------|---------------------------|
| 15m | 0.23〜0.32% | **15.8〜42.8%** |
| 1h | 0.53〜0.69% | **14.5〜19.0%** ← これまでの全評価がここ |
| 4h | 1.17〜1.47% | 6.8〜8.6% |
| **1d** | **3.15〜3.94%** | **2.5〜3.2%** |

往復コストは元本の 0.150%（手数料 0.055%×2 + スリッページ 0.02%×2）で固定です。
分母である値幅を大きくする以外に、この比率を下げる方法はありません。
**1時間ATRで損切りしていた間、毎トレード R の15〜19%をコストに払っていました。**

「もっと良いシグナルを探す」より先に、ここを直します。

## 1. 回数の問題をどう扱うか

日足規模のロジックは1銘柄では年20〜25回しか発火せず、`min_trades=100` に届きません。
これは EH-07 で2回先送りしてきた論点です。取れる道は3つ。

- ゲートを緩める → 判定が甘くなる。**採用しない**
- 銘柄を増やして回数を稼ぐ → v2 で採ったが、**BTC単独指示により廃止**
- **期間を伸ばして回数を稼ぐ** → 現行。`configs/eval_v3_btc.yaml`

### 経緯（v2 の6銘柄バスケット — 記録として保存）

`configs/eval_v2.yaml` で6銘柄（BTC / ETH / SOL / BNB / XRP / DOGE）を事前に宣言し、
「機構なら別の銘柄でも効くはず」という追加検証も兼ねていました。
`configs/eval_v2_oos.yaml`（LTC / DOT / AVAX / LINK）での答えは**「効かない」**で、
Set A は14本すべてプラスなのに Set C は11本がマイナスになりました。

さらに BTC 単独に絞ってわかったのは、**6銘柄版が買い持ちを +76pt 上回っていた理由が
「崩れたアルトをショートできたから」**だったことです。バスケットは回数を稼ぐ手段の
つもりでしたが、実際には成績の主因になっていました。

### 現行（v3 = BTC単独・期間で稼ぐ）

Binance に BTCUSDT の15分足がある全範囲を、ほぼ等長の3期間に割ります
（ウォームアップ400日を確保して 2018-10 から）。

| 期間 | 範囲 | 年数 | n（中心設定） |
|---|---|---|---|
| Set A | 2018-10-01 〜 2021-04-30 | 2.58 | 56 |
| Set B | 2021-05-01 〜 2023-12-31 | 2.67 | 51 |
| Set C | 2024-01-01 〜 2026-08-22 | 2.64 | 57 |

**それでも 100 には届きません。** 年22回 × 2.6年 ≒ 57 で、これは
「日足規模 × 1銘柄」の構造的な上限です。ゲートは下げず、代わりに
**符号の一致（機構の再現性）** と **プール後の t 値（推定の精度）** で読みます。

各変種のばらつきから t=2 に必要な n を逆算すると（`scripts/pooled_significance.py`）、
中心設定でちょうど 100 でした。**ゲートの 100 は妥当**で、届かないのは戦略側の事情です。

**コストとゲートは v1 から一貫して同一**です。緩めた点はありません。
同時保有は1枠（証拠金 30 ≤ 元本 300）。`fixed_margin` サイジングは建玉サイズが
資産残高に依存しないので、リスク額を k 倍するとリターンもDDもほぼ k 倍になります。
買い持ちとの比較で **リターン÷DD** を使うのはこの性質のためです。

## SH-01

### 日足規模のトレンド継続

**CLAIM:** 20日高値を4時間足の終値で上抜けたら買い、10日安値を割ったら降りる。安値側は対称。
損切りは **日足ATRの1.5倍**。固定利確は置かない。

**なぜこの形か:**
仮説というより、**コスト測定から逆算した最小構成**です。日足ATR基準の損切りにすると
コストが R の 2.5〜3.2% に収まり、初めて「エッジがあるかどうか」を議論できる土俵に乗ります。
これまでの学び（固定利確を置かない・トレールを締めない・突破に対して待たない）を
すべて既定値として持ち込みます。

**なぜ市場が織り込めていないか:**
織り込まれている可能性は高いと考えています。日足ブレイクは広く知られた形です。
ただし **これは「勝てる秘密」の候補ではなく、コスト構造が正しいときに何が残るかを測る基準線**です。
ここがゼロ近辺なら、より複雑なロジックを試す意味もありません。

**誰が損するか:** 明確な相手はいません。基準線なので、そこは主張しません。

**TESTABLE:** 費用後 EV > 0、最大DD ≤ 20% を Set A / B / C すべてで満たす。
n ≥ 100 は据え置くが、BTC単独では期間ごとに到達しないため、
プール後の n と t 値、および3期間の符号一致で読む（[経緯](#1-回数の問題をどう扱うか)）。

**棄却条件:** 3期間のいずれかで EV ≤ 0。または DD が20%を超える。
または**買い持ちに対して、リターン÷DD で3期間とも下回る**。
（後者は BTC 単独に絞ってから追加した。BTC を持つだけで済むなら、ボットを動かす理由がない。）

**ノブ（1点ずつ）:** 入口日数 / 退出日数 / 損切ATR倍率 / ATRの足 / 入口判定の足 /
地合いフィルタ / 方向 / EH-06拒否フィルタ。

### EH-06 拒否フィルタの位置づけ

EH-06（個人と上位の建玉が逆を向く）は3期間を通じて **向きに情報がある**ことが確認済みですが、
単独で入る理由にはなりませんでした（[postmortem](./postmortems/2026-08-23-edge-06-09-and-fee-bug.md)）。
そこでここでは **「群衆と同じ側に立つ取引を拒否する」フィルタ**として載せます。

- `veto_*`: 買いのとき群衆が買いに偏っていたら見送る（売りは対称）
- `veto_*_ctrl`: 拒否の向きを反転した対照

判定は絶対EVではなく、**基準線との差が3期間で同符号か**で行います。

**結果: 効きませんでした。** 3期間とも基準線をわずかに下回ります
（+2.608/+3.113/+0.312 対 基準線 +2.760/+3.120/+0.380）。
突破が起きる場面ではそもそも群衆が上位トレーダーほど買っておらず、
1.0σの拒否フィルタは6銘柄・1年で数件しか発火しませんでした。
向きに情報があることと、トレンド追随の入口を改善することは別でした。**打ち止めます。**

### 近傍（SH-01N）— BTC単独・全履歴3期間

中心 `sh01n_center`（= `tp_4atr`）の周りを14本で地図にしました。

| | Set A | Set B | Set C | プール |
|---|---|---|---|---|
| n（中心） | 56 | 51 | 57 | **164** |
| EV（中心） | **+1.951** | +0.528 | +0.456 | **+0.989** |
| t（中心） | +2.78 | +0.80 | +0.72 | **+2.57** |
| 最大DD（中心） | 2.8% | 5.3% | 7.6% | — |
| EV プラス（14本中） | 14 | 13 | 14 | 12本が t ≥ 2 |

**42通り中41通りで EV プラス。** 唯一のマイナスは利確を近づけた `tp_2` で、
既知の「勝ちを早く切ると死ぬ」と同じ向きです。面として整合しています。

EV の水準は **+1.951 → +0.528 → +0.456 と時間とともに落ちています**。
機構が消えたのではなく（符号は保たれる）、取れる幅が縮んでいます。

### 反証テスト

シグナルを丸ごと遅らせても残るかを確認しました（BTC単独・全履歴）。

| | EV(A) | EV(B) | EV(C) |
|---|-----|-----|-----|
| 基準（`tp_4atr`） | +1.951 | +0.528 | +0.456 |
| 1時間遅らせる | +2.002 | +0.646 | +0.282 |
| **1日遅らせる** | **+1.257** | **+0.333** | **+0.320** |

減衰はしますが3期間とも消えません。実装上の先読みではないと判断します。

さらに、全価格に 1e-6（往復コスト 0.15% に対して 0.0001%）の擾乱を与えても
トレード数は完全一致、EV の差は 0.001 でした。同値判定のきわどさに乗った結果ではありません
（`scripts/jitter_sensitivity.py`）。

### 買い持ちとの比較 — ここが採用の障害

生リターンの比較は投下資本が違う分だけ戦略に不利です（証拠金 30 / 元本 300）。
`fixed_margin` はリスク額を k 倍するとリターンもDDもほぼ k 倍になるので、
**リターン÷DD** が資本量に依らない比較になります。

| | Set A | Set B | Set C |
|---|---|---|---|
| BTC 買い持ち | **+768.9%**（DD 72.2%） | −27.1%（DD 77.2%） | **+81.4%**（DD 53.8%） |
| 中心設定 | +36.4%（DD 2.8%） | +9.0%（DD 5.3%） | +8.7%（DD 7.6%） |
| ret/DD | +13.02 対 +10.65 | +1.69 対 −0.35 | **+1.14 対 +1.51** |
| ret/DD で勝った変種 | 7/14 | 13/14 | **2/14** |

下落期は圧勝、上昇期は負ける。**直近 Set C はリスク調整後でも負けます。**
戦略が売っているのはリターンではなく **DD**（2.4〜12% 対 53〜77%）です。

6銘柄版が買い持ちを +76pt 上回っていたのは崩れたアルトをショートできたからで、
BTC 単独にその機会はありません。**「買い持ちに勝つ」はバスケットの性質でした。**

## 共通ルール（v1 から継続）

1. ノブは1点だけ
2. 対照を必ず入れる。合否ではなく差を読む
3. **3期間（A/B/C）すべてで判定**。未使用の期間を残さない
4. `min_trades=100` は据え置き。届かないときは下げるのではなく、
   **ばらつきから必要 n を逆算して**それを書く（`scripts/pooled_significance.py`）
5. コストは緩めない
5b. **買い持ちと比べる。** リターン÷DD で3期間とも負けるなら、ボットを動かす理由がない
6. 合成データで合否を出さない
7. 組合せだけが効く設定は、採用前に近傍を地図にする
8. **実行環境も固定する。** 入力の sha256 だけでは再現しない
   （`requirements.lock.txt`／レポートに python・pandas・numpy と lock のハッシュを記録）
