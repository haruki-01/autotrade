## 低速側（SH-01）— コストから逆算した設計

**現行の検証環境は `configs/eval_v3_btc.yaml`（BTC-USDT単独・全履歴3期間）。**
6銘柄バスケット（v2）と宣言外バスケット（v2_oos）は記録として残すが、以後の判定には使わない。

> **現行の検証枠は固定ブラケット（2026-08-25）**
> リスクリワード1:2固定・保有上限6時間・損切り0.35%/利確0.70%
> （実測で6時間以内決済率89.9%）。
> 判定基準が理論から出る（ドリフト無しなら当たり率1/3）ので、
> 勝率33%台なら情報ゼロと即断できる。頻度も1枠で月260回まで出るので制約外。
> **15分足の価格・出来高・時間帯からは25条件×3期間で情報が出なかった。**
> 損益分岐47.6%に対し最大の上振れが対照比+1.5pt。
> → [BRACKET_FRAME.md](../BRACKET_FRAME.md)

> **ゲートは2軸（2026-08-24）**
> `min_trades: 100` = **測れるか**（落ちたら判定保留）／
> `min_trades_per_month: 50` = **回す価値があるか**（落ちたら不合格）。
> 入口判断は1分〜15分足。
> **SH系は後者で全滅**（1.6〜1.8回/月）。頻度帯 50+/月 を狙って作ったロジックは
> 記録済み258本の中に1本もありません。
> → [月50エントリー要件](../postmortems/2026-08-24-trade-rate-requirement.md)

BTC単独・全履歴3期間の中心設定 `sh01n_center`: EV +1.951 / +0.528 / +0.456、
DD 2.8 / 5.3 / 7.6%、n=56/51/57、**プール n=164 / EV +0.989 / t=+2.57**。
1日遅らせても3期間プラス。1e-6 の価格擾乱でもトレード数は不変。

**採用不可の理由:**

1. **期間ごとにゲートに届かない。** n≈55 で t=+2.78/+0.80/+0.72。
   `min_trades=100` は年22回×2.6年＝57 なので1銘柄では原理的に到達不能。
   ただしばらつきから逆算した必要 n が中心設定でちょうど 100 なので、**ゲートは妥当**。下げない
2. **買い持ちに勝てない。** Set C は +8.7% 対 +81.4%。リターン÷DD でも 12/14 が負ける。
   勝つのは下落期（Set B）だけ。売り物は DD（2.4〜12% 対 53〜77%）のみ
3. EV の水準が時間とともに落ちている（+1.951 → +0.528 → +0.456）

**頻度要件により上の選択肢はすべて無効になりました。** 次にやるべきことは3つ。

1. **約定モデル**（前提）— 指値の未約定を数える。月50回ではコスト前提が結果を決める。
   入口を指値にできれば年間コストは 81 → 51 USDT（元本の10%分）
2. **複数枠**（前提）— `engine.py` は1枠のみ。月50回 × 保有48時間なら3.3枠必要
3. **月50回帯で最初から設計** — 15分足ATR（0.23〜0.32%）の1〜1.5倍を取りに行く形。
   コストの床 0.135（指値なら 0.086）を1回あたりで超える必要がある

> **再現性:** 2026-08-23 以前の数値は再現しません（VM 再構築で23本中11本が変化）。
> 正は 08-24 の再実行。`requirements.lock.txt` で環境を固定済み。
